# MiniMaxH3 多参考工作流接入

## 交付契约

- 独立导入用户的 API 工作流，保留已有工作流与已部署的 Qwen 选择器功能。
- 参考图片 1–6 张，首张必需；参考视频、音频各 0–2 项。未提供的可选槽位与孤立加载器必须删除，不使用占位输入。
- 提示词、种子、时长、选择器宽高比/百万像素/对齐倍数、二采目标百万像素均有显式绑定。
- 主结果只保存二采节点 98 的带音频 MP4，不能把一采预览当最终结果。
- 托管素材在冻结与执行时检查权限、类别、版本；图片/视频/音频传输上限分别 20/200/50 MiB。

## 执行顺序

1. 合并已有选择器能力，扩展视频任务与可选媒体上传。
2. 补齐普通生成和配置试运行的通用媒体上传接口。
3. 隔离构建，跑 Java21 回归并部署合并版。
4. 在线校验、真实最小/满槽试运行、发布独立模型。
5. 浏览器检查配置与普通生成，记录映射与回滚。

## 变更边界

不修改数据库结构，不修改 ComfyUI 源码或全局 Python 依赖，不改变既有模型启用状态，不提交或推送 Git。原来的 MiniMax 两图工作流保留；旧模型记录已不可用，因此新建独立模型。
