# 对外 MCP 一期完成记录

## 实现

新增默认关闭的 `/api/mcp` 入口及 19 个工具。外部 Agent 将结构化草稿提交到已有项目。剧本、分镜、提示词、资产沿用现有业务命令、事务、版本和资源事件。项目凭证支持签发、查询和撤销，每次请求校验有效期、项目归属与实时成员权限。

图片、视频和音频使用专用项目 HTTP 入口传输。上传沿用托管媒体、类型识别、大小校验和内容哈希。绑定与替换使用媒体 ID 和目标版本，下载支持 `HEAD` 和字节范围。接入说明见[项目 README](../../../README.md)，工具和文件契约见[实施方案](development-plan.md)。

前后端开发版本为 1.4.0。凭证表使用 `V1.1.4.0.0__create_mcp_project_credentials.sql`。v1.3.0 正式发布提交中的迁移脚本保持原样，校验和已加入不可变校验。 [上游 v1.3.0](https://github.com/Stonewuu/ai-fusion-video/releases/tag/v1.3.0)

## 服务器部署

2026-11-12 已在融光内网实例切换后端，镜像为 `ai-fusion-video:project-mcp-1.4.0-246c17287c23`，镜像 ID 为 `sha256:c2076835f96e33190760043af0a9435dd4e3d84a892b92dc710302066a919af3`。上线镜像在服务器原有后端基线上加入 MCP 一期变更。后端健康检查通过，Flyway 已应用凭证表迁移 `1.1.4.0.0`。前端、代理、MySQL 和 Redis 的容器身份、启动时间和重启次数通过切换前后对比。

同一候选镜像在服务器隔离数据库副本通过 19 个工具发现、跨项目权限、版本冲突、同键重试及 PNG、MP4、WAV 上传绑定和下载哈希校验。旧镜像也在已迁移副本上通过启动验证。发布前的数据库备份与 Compose 配置已按发布编号 `20261112-project-mcp-246c17287c23` 归档。

从本机使用服务器内网 CA 和 curl 校验 HTTPS 证书，登录页及普通 API 返回 `200`，MCP 入口 `/api/mcp` 返回预期的项目凭证挑战 `401`，未授权来源返回 `403`。初次部署时，Python 3.14 严格 TLS 校验因旧 CA 缺少 Key Usage 扩展而拒绝连接。

### 内网 CA 修复与线上实测

2026-11-12 使用原 CA 密钥与主题重签公证书，增加关键 `keyCertSign` 与 `cRLSign` 用途。新 CA 在原服务端证书上通过 OpenSSL 和 Python 3.14 严格验证。旧 CA 访问登录页返回 `200`，Chrome 原登录会话刷新后仍可打开仪表盘。旧公证书及验证记录已按变更编号 `20261112-ca-keyusage-4c8dcedfb103` 归档。

使用 20 分钟、单项目读写凭证，Codex CLI 通过线上 HTTPS 发现 19 个工具并实际完成 8 次融光工具调用。独立读回确认剧本分集、资产及图像、视频和音频绑定已落库。Agent 通过 HTTPS 上传与下载合成 PNG、MP4、WAV，每份原件的字节和 SHA-256 一致。验收结束已撤销凭证，重试返回 `401`，临时项目从项目列表移除。
