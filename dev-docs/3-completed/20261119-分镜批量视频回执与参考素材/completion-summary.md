# 分镜批量视频修复

## 生产核对

项目 21 的批次中，首条视频任务 #84 独立回收。随后并行等待的五条子任务里，#85、#86、#87、#89 已生成、回填且子 Agent 已完成。父 Agent 等待 #88，直到批次取消也未记录其余四条的回执。

该批次五条成功视频的请求各使用了一张场景图，漏掉了镜头绑定且当时可用的角色图和道具图。旧版生成和回填还覆盖了这五条镜头的原视频提示词。上一版提示词修复上线后，生产单镜头任务 #91 的提交原文、ComfyUI 节点提示词和当时保存的分镜提示词逐字一致。

## 实现

- 父流水线等待期间，每个已完成的子任务单独写入可重放的完成回执。同一回执只追加一次。父 Agent 收齐本轮真实结果后再恢复执行。
- 项目分镜视频采用目标镜头的已校验版本和实际绑定。模型支持时，按画风（有参考图时）、角色、道具、场景的顺序组合参考图。每个子资产校验所属项目、访问权限和对应类型。绑定失效、缺图或超出模型能力时，在供应商提交前返回原因。
- 已有视频提示词继续按保存原文生成。没有保存提示词的镜头仍可使用 Agent 编写的内容。首尾帧使用镜头已保存的首尾帧字段，并遵守模型能力和模式互斥约束。

## 验证与发布

- 隔离 MySQL、Redis、HTTP 和供应商桩验证了双镜头并行等待。第二条仍未结束时，SSE 重连已经收到第一条成功回执。最终两个子任务各有一条回执、各有一条供应商提交，两段视频均回填。
- 两个镜头分别收到三个绑定图和一个绑定图，顺序与内容均核对。多行提示词按原文发送。MiniMax H3 工作流槽位和既有等待恢复的定向回归一并通过。本轮共 14 项通过。
- 本次实现与定向验证已完成，待提交和部署。生产读取用于对照，真实批量成片待验收。
